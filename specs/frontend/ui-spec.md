unclear or missing, update the spec first, then the code. Endpoint details are in `specs/backend/api-spec.md`.
Sketches go in `docs/screens/`.

### Dark mode (2026-10-27; `specs/2026-10-27-dark-mode/`)
**Light is the default for everyone (owner, 2026-10-27, until the owner approves the dark mode; `specs/2026-10-27-light-default-theme/`).** The site starts in Light even when the device is dark; Dark comes only when the visitor picks it with the button. A **Theme** button in the header (an icon, from tablet width) and in the Menu (icon and words, on a phone) cycles **Light, Dark, System** and says which is chosen (for a screen reader too); its first state is Light. All three choices are remembered in the browser (`localStorage`, key `swifthealth.theme`: `light`, `dark` or `system`); with no key, or any other value, the choice is Light. System is the only choice that follows the device, and it keeps following it while the page is open. The tab's `data-theme` attribute on `<html>` is `light` or `dark`: a few lines of script in the `<head>` set it before the first paint, so there is **no flash**. Without script the page is Light (there is no `prefers-color-scheme` rule), and the browser's own parts (fields, scrollbars) are light too (`color-scheme: light`).
**How the colours work:** the components never write a colour; they use the tokens above. Dark mode changes the *values* of the role tokens under `html[data-theme="dark"]` only, and Tailwind 4's `dark:` variant (`@custom-variant dark`, on `data-theme="dark"`) is used for the few things a token cannot say. Tokens split into two kinds:
- **Role tokens (they change):** `page` `#f6f3ec` to `#0e1514` (the page), `surface` `#ffffff` to `#16201f` (cards, fields, dialogs; replaces `bg-white`), `ink` to `#e7eceb`, `ink-soft` to `#a7b6b3`, `line` to `#2d3c3a`, `forest` (text, links, headings, the focus ring) to `#7fc6e8`, `pine-100` to `#1c4256`, `pine-50` to `#152f3b`, `open` `#6fd6a0` on `open-bg` `#12301f`, `closed` `#b9c6c2` on `closed-bg` `#232d2b`, `amber-ink` `#f2c668` on `amber-wash` `#3a2c0a`, `whatsapp-dark` `#3fb59f`, `alert` (red text and the 112 card's border) `#b3261e` to `#ff8a80`.
- **Constant tokens (they never change):** `pine`, `pine-dark`, `accent`, `sky`, `sky-pale`, `paper`, `amber`, `on-amber` `#1d2421` (text on the Sponsored tag), `emergency` `#b3261e` (the red SwiftRescue button and the Call 112 button, white text), and `snow` `#ffffff` (a white that stays white: the white button on the blue bands of the home and Find pages; the Find page's first button is that button since 2026-10-27). So the header, the hero, the buttons, the logo and the red buttons look the same in both modes; `bg-forest` (four places) became `bg-pine` for this reason.
**Kept as they are, on purpose:** the map tiles (the map keeps its light look; its popups, pins and credit follow the tokens), the photos, the logo, the **112 card (a red border and the red Call 112 button, in both modes)**, and the **Security QR code, which is always dark on white** (it has a white frame whatever the mode). Every text and background pair is at least 4.5:1 in both modes and every button edge and focus ring at least 3:1 (`tests/unit/design-tokens.test.ts`); Lighthouse Accessibility is 100 in both modes on the pages checked. The browser's address-bar colour stays the header blue.

### Buttons and text
- **Password fields** (owner, 2026-10-25): **every** password field is the one shared component `components/ui/PasswordField.tsx` (the staff login, the Security screen, the staff accounts screen, and the sign-up, change-password and reset-password screens to come; a test fails if a screen writes its own password input). It has an **eye button inside the right edge** of the field: a real button (`type="button"`, so it never submits the form) with `aria-label` **"Show password"** / **"Hide password"** and `aria-pressed`, **48 px wide and as high as the field (at least 48 px)**, a 20 px icon that is only decoration, reachable and operable with the keyboard (Tab, Enter, Space). Pressing it changes only the `type` of the **same input** (password or text), so a paste, the caret and the browser's password manager keep working; `autocomplete` is set by the screen (`current-password` or `new-password`) and never changes; the keyboard's capital letter, autocorrect and spell check are off. **The password goes back to hidden when the form is submitted and when the page is left** (`pagehide`, also when the browser keeps the page for the back button); a new draw of the field starts hidden. 16 px text, the field has room at its right (`pr-14`) so the text never runs under the button, it fits at 320 px, and the colours are the design tokens (the blue palette: `forest` icon, `pine-dark` on hover), none written by hand, so a dark mode changes them in one place.
- **Phone numbers as text** (owner, 2026-10-13): a number is stored as `+2348031234567` and **shown for reading in the local format `0803 123 4567`**
  (the leading 0, then groups of 4, 3 and 4 digits), everywhere it is shown as text: one function (`formatPhoneForReading` in
  `lib/formatters/phone.ts`) does it. A number that is not a Nigerian number is shown as it is stored. The links do not change: `tel:+234…`
  and `wa.me/234…` stay international. A masked number keeps the same shape ("0803 *** 0001").
- **Primary** (Call, Retry): `pine` background, white text; `pine-dark` on hover and press. **Secondary** (Directions,
  See all, Clear filters): white background, `pine` border, `forest` text; `pine-50` background and `pine-dark` border on
  hover, `pine-100` on press. **On dark** (the home page hero button, 2026-10-12): white background, `pine-dark` text (8.9:1),
  `pine-50` on hover and `pine-100` on press; the `pine` button would vanish on the dark hero. **Emergency** (SwiftRescue only): `emergency` background, white text. 16 px text,
  semi-bold, at least 50 px high (never under 48 px), radius 12 px.
- Every piece of text is 16 px or larger, including badges, the area line and "Verified 3 days ago" (NFR-10). Card titles
  are 18 px. The system font stack is used; no web font is downloaded.
- Cards: white, 1 px `line` border, 16 px radius, `shadow-card`, 16 px inside.
- Status is shown with words as well as colour ("Open now", "Closed", "Verification due").

### Accessibility and performance (NFR-01, NFR-04, NFR-10)
- Tap targets at least 48 × 48 px; body text 16 px or larger; visible focus ring.
- **Focus ring** (owner's decision, 2026-10-09): 3 px, 2 px offset. `forest` on light backgrounds (5.6:1 on white, 5.1:1 on
  `paper`); `paper` on a `forest` background (5.1:1). A container with a `forest` background has the class `on-dark`, which
  switches the ring for everything inside it (the header and the Find page hero). Both are at least 3:1 (WCAG 2.2, 1.4.11).
  A test in `tests/unit/design-tokens.test.ts` checks it.
- **Icons** (owner's decision, 2026-10-09): from `lucide-react`, imported one by one by name (never the whole set, never a
  dynamic icon). They are decorative (`aria-hidden`) and always sit next to a text label; an icon is never the only content
  of a button or link, and it never carries information alone.
- Works from 320 px wide; no sideways scrolling.
- Pages are server components unless they need interaction; only maps, forms and filters are client components.
  One exception: the results list of `/search` is a client component too. It loads in the browser with a 45 second limit
  (see "Standard states"), because the free API can take about a minute to wake and the hosting gives up on a server page
  after about 30 seconds. This means results need JavaScript (revisit after the Render upgrade, `LOG.md`).
- **The home page's loading rules** (owner, 2026-10-13, after a Lighthouse run of 37 on mobile; requirements R42 to R47): the heading, line,
  button and text are in the first HTML (no JavaScript is needed to show them); each screen width downloads one hero photo only (a `<picture>`
  with a phone-only source); the hero photo loads first (`fetchpriority="high"`, not lazy) and the owners' photo is natively lazy; every
  link on the home page has `prefetch={false}`, so no other page's code is downloaded before it is asked for; no map, chart or search
  code is downloaded; the photos and `/_next/static` are cached for a year (`netlify.toml`; a new photo gets a new file name); the header
  and the footer are server components (the route group of the page decides which one, see "Layout"); only the Menu button is client
  code; the site uses the system font stack, so no font blocks the text.
- A visitor's position is kept in `sessionStorage` for the tab only, rounded to 3 decimals. It is never in a page address,
  a cookie, `localStorage` or a log, and it is sent only as `lat` and `lng` to `GET /search`.
- Images compressed; no large libraries on public pages except Leaflet on the map view.
